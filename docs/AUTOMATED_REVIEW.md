# Automated review using external labels

PolyViz now has a free local reviewer trained on existing researcher-coded legislation. You do not need to label the 52-bill sample to run it. The earlier blind human-review tools remain optional; their sessions and annotations are preserved.

## Source selected

The Pennsylvania Policy Database Project (PPDP) dataset is distributed through the [Comparative Agendas Project](https://comparativeagendas.net/datasets_codebooks). Research describing state legislative agendas identifies PPDP as hand-coded by researchers using an adapted policy codebook: [Policy agendas of the American state legislatures, 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12283944/).

The inspected CSV contains 102,727 records from 1979–2016. The importer retains 79,510 eligible, noncommemorative regular-session bill records with valid labels and descriptions. It excludes resolutions, joint resolutions, other non-bill types, and unrecognized identities. Exact filters and counts are recorded in the evaluation report.

Each record has one native primary major topic and subtopic. Those are externally assigned labels, not labels generated by PolyViz. They are also not a complete list of every topic the bill might address.

Source catalog: `data/external_sources.json`. Source snapshot SHA-256:

## Other sources investigated

- **NCSL:** its [database guide](https://www.ncsl.org/resources/ncsl-databases-user-guide) says staff read bills and manually assign topics. This is promising for topic-specific state checks, but no bulk labeled export was acquired in this task.
- **NYU Furman:** its [land-use tracker methods](https://www.furmancenter.org/data-tool/land-use-reform-tracker/) describe human coding and AI-assisted coding with human validation, with per-record coding-method flags. It has narrower housing/land-use scope. Download requests returned HTTP 403, so its records were not used.
- **2025 all-state agendas dataset:** its large multi-label outputs are machine-generated estimates. Those should not be relabeled as confirmed human ground truth. OSF downloads were unavailable here.

## Model and evaluation

The reviewer learns source-native primary topics from legislative descriptions using word/bigram TF-IDF and a linear support-vector classifier. This is supervised learning on externally coded legislation, not generic embedding similarity.

To limit leakage:

1. Normalize description text for punctuation and numbers.
2. Group matching descriptions, keeping only the earliest occurrence of groups whose major label is consistent.
3. Exclude groups with conflicting major labels; report those exclusions.
4. Train on sessions starting before 2011 (40,482 distinct descriptions).
5. Fit monotone sigmoid calibration on 2011–2012 sessions (1,946 descriptions).
6. Evaluate on later sessions starting in 2013 (3,928 descriptions).

The vocabulary is fitted on training descriptions only. Test labels are not used for fitting or choosing score thresholds. Similar paraphrases can remain after this normalization; the test is not a guarantee of absence of all near-duplicate wording. Group-conflict filtering is source curation and reduces the population being evaluated.

Initial library calibration emitted numerical warnings on this platform. The final implementation uses stable elementwise sigmoid gradients, was rerun without those warnings, and fails on nonfinite scores or calibration failure. It uses smoothing for small calibration classes. Calibration scores are not guaranteed confidence for other states or time periods.

Saved results: `examples/evaluation/external/pa_primary_report.json`.

| Measurement | Result |
|---|---:|
| Source-primary-topic agreement, all 3,928 test bills | 83.2% |
| Macro F1 | 72.1% |
| Correct source primary topic among top three suggestions | 94.8% |
| Test bills meeting fixed score >= 0.80 and margin >= 0.25 | 2,669 / 3,928 (67.9%) |
| Primary-topic agreement within that selected subset | 94.2% |

The subset's 94.2% must always be reported alongside its 67.9% coverage. It is not the overall score. These results evaluate older Pennsylvania source-native single-label classification; they are NOT accuracy for all 50 states, PolyViz multi-label categories, or affected-sector tagging.

## Run the automated reviewer

The model has already been trained in this checkout. Review a classifier output:

```bash
.venv/bin/python -m polyviz.external_review review data/generated/large_hybrid.json --output data/generated/large_external_review.json
```

The command also accepts a single raw bill or an array of bills. For raw input it uses the existing keyword normalizer; for a canonical `bills` envelope it preserves the supplied classifier topics and attaches `external_review` without changing them.

Output includes the top three native topic suggestions, scores, a score margin, broad category overlaps, domain-shift flags, and any exact source-label match. These are kept separate from `topics` and `affected_sectors`.

Statuses:

- `external_native_label_available`: that bill identity exists in the source lookup. Its native label is returned, along with whether normalized input text matches the source description. This does not verify a different bill version or the custom PolyViz topic set.
- `uncertain`: score or margin is below the fixed controls.
- `native_category_has_no_simple_crosswalk`: there is no simple mapping into the current ten topics.
- `broad_topic_agreement`: a high-scoring native category broadly overlaps a supplied topic.
- `possible_topic_disagreement`: a high-scoring native category broadly overlaps a topic not assigned by the supplied classifier.

Every result explicitly retains `verification_status: polyviz_labels_not_verified`. Agreement between two classifiers is not external truth. Broad overlaps are hypotheses for review, not a silently adopted taxonomy crosswalk.

## Current six-state sample

On the 52-bill current sample, the reviewer returned:

- 8 broad-topic agreements.
- 4 possible-topic disagreements.
- 5 high-score native categories without a simple crosswalk.
- 35 uncertain cases.
- 0 exact source-label matches, because the sample contains no Pennsylvania bills.

See `examples/evaluation/external/six_state_review_summary.json`. These are review statuses, not an accuracy measurement. The high uncertainty is useful: transfer from older Pennsylvania descriptions to current bills in other states is not yet established.

## Fresh checkout setup

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-reviewer.txt
.venv/bin/python -m polyviz.external_review download
.venv/bin/python -m polyviz.external_review train
```

Downloads are public, and training/inference run locally. No paid API, account, API key, or credits are used. The source is approximately 43 MiB. The downloader caps size and checks expected CSV headers; training checks the inspected source checksum. The training command refuses to overwrite an existing model, so use a new `--model-dir` for another experiment.

Models are serialized locally with joblib. The tool never downloads serialized reviewer models; it builds them from the inspected CSV. Raw source data, source lookup, and model weights are not committed. Dependency versions used for this checkout are also recorded in `requirements-semantic.lock.txt`; the reviewer itself needs only `requirements-reviewer.txt`.

## What is automated now

External-label ingestion, duplicate controls, temporal training/calibration/testing, native label prediction, exact source-label lookup, and review triage run without asking the user to label bills. No manual session is required to run those steps.

What is not solved: a complete external multi-label reference across every state matching our direct-topic/affected-sector definitions. PPDP sometimes assigns sector-specific tax bills to their sector, whereas the user-selected design separates the instrument from affected sectors. The source codebook's law category also includes family/civil matters, and community development is broader than residential housing. Never treat unlisted secondary topics as negative labels.

The next defensible extension is acquiring compatible external labels from additional states/topics, documenting each mapping, and evaluating transfer. The saved provisional assistant labels remain development material, not confirmed ground truth. Human review can be reserved for unresolved ontology/source disagreements rather than making the user label every bill.

## Contextual alignment suggestions

The reviewer now adds a separate `policy_alignment` object. Native model predictions,
existing `topics`, and affected-sector fields remain unchanged. `applied: false` and
`verification_status: not_verified` identify every suggestion as advisory. Explicit
textual rules distinguish direct topics from affected sectors, flag taxonomy gaps,
and flag summaries describing only renaming for exclusion from substantive-policy
analysis. These rules use the existing 0.8 score and 0.25 margin gates for topic
suggestions; they do not lower uncertainty thresholds. Renaming detection is a
separate text rule. Exclusion also remains a suggestion.

Run the updated review:

```sh
.venv/bin/python -m polyviz.external_review review data/generated/large_hybrid.json --output data/generated/large_external_review_v3.json
```

CLI output includes both `native_review_summary` and `policy_alignment_summary`.
The document retains the original `review_summary` field for compatibility.
The nine development cases are recorded in
`examples/evaluation/external/contextual_alignment_audit.json`. They informed
these rules and cannot establish independent accuracy improvement.

Findings: three transportation/healthcare additions, one education removal from a
school-tax exemption, one pure-renaming exclusion, two contextual agreements, and
two remaining gaps (business licensing and local-government financing/governance).
No category is silently added to the production taxonomy. An education sector
suggestion does not independently add an education policy topic. Context rules
are limited to the supplied title and summary; they are not a full statutory audit.
The school-tax interpretation is supported by the
[official New York S9989 page](https://www.nysenate.gov/legislation/bills/2025/S9989).

## Independent cross-state transfer check

```sh
.venv/bin/python -m polyviz.transfer_audit --download
```

This free public-data audit leaves the Pennsylvania model unchanged and compares
its primary-topic predictions with published Florida Policy Agendas Project
codes. Model artifact hashes are checked before and after prediction. The report
is `examples/evaluation/external/fl_transfer_report.json`.

Of 4,119 source rows, later-year bill titles are blank; invalid codes, conflicting
labels, duplicate titles and bill identities, and exact normalized overlap with
Pennsylvania fitting/calibration text are filtered. The retained 738 titles are
all from 1993. Agreement is **53.7%** overall; the fixed high-score subset has
**74.1%** agreement at **39.8%** coverage. These results demonstrate a substantial
transfer limitation, even for high scores. They are not current all-state,
PolyViz multi-label, or policy-versus-sector accuracy estimates. Florida labels
were not used to fit the model or tune thresholds. Source codes are research
project labels; the file does not document per-record coding validation.

Keep this reviewer advisory. Broader labeled coverage with comparable input text
and explicit policy/sector mapping is needed before automatic label replacement.
